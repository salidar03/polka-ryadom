# Как развернуть «Полка рядом»

Система состоит из трёх частей:

| Часть | Что это | Где лежит |
|---|---|---|
| Сервер (API) | Python 3.12, FastAPI | `backend/` |
| Интерфейс | React + Leaflet (сборка Vite) | `frontend/` |
| База | PostgreSQL в Docker или файл SQLite без Docker | `backend/polka.db` |

Нужен интернет: карта (OpenStreetMap) и маршруты рейсов по улицам (OSRM) грузятся из сети. Без сети система работает, но без подложки карты, а маршруты строятся по прямой.

Выберите вариант:

- **А. Docker** — одна команда, всё в контейнерах. Удобно для показа и сервера.
- **Б. Без Docker** — Python и Node.js на компьютере. Удобно для разработки.
- **В. Два ноутбука** — показ «клиент на одном, ПВЗ на другом».
- **Г. Сервер в интернете** — постоянный адрес для жюри.

---

## А. Docker

1. Установите **Docker Desktop**: https://www.docker.com/products/docker-desktop/ (Windows: при установке согласитесь включить WSL 2 и перезагрузите компьютер). На Linux — Docker Engine и плагин compose.
2. Скачайте проект:
   ```bash
   git clone <адрес репозитория>
   cd polka-system
   ```
3. Запустите:
   ```bash
   docker compose up --build -d
   ```
   Первый запуск скачивает образы и библиотеки — 5–10 минут.
4. Откройте:
   - интерфейс — http://localhost:8080
   - документация API — http://localhost:8000/docs

Полезные команды:

| Что сделать | Команда |
|---|---|
| посмотреть логи | `docker compose logs -f api` |
| остановить | `docker compose down` |
| обновить после `git pull` | `docker compose up --build -d` |
| начать с чистой базы (удалит все аккаунты и заказы) | `docker compose down -v` и снова `up` |
| резервная копия базы | `docker compose exec db pg_dump -U polka polka > backup.sql` |

## Б. Без Docker

Нужны **Python 3.12** (https://www.python.org/downloads/, при установке отметьте «Add Python to PATH») и **Node.js 20 LTS** или новее (https://nodejs.org).

### Windows — одной кнопкой
Дважды щёлкните `start-lan.bat` в корне проекта. При первом запуске он сам создаст окружение Python и поставит зависимости, потом откроет два окна — «Polka API» и «Polka WEB». Откройте http://localhost:5173.

### Вручную (Windows, Linux, macOS)
```bash
# 1. сервер
cd backend
python -m venv .venv
# Windows:            .venv\Scripts\activate
# Linux / macOS:      source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 2. интерфейс — в другом терминале
cd frontend
npm install
npm run dev
```
Откройте http://127.0.0.1:5173. База — файл `backend/polka.db`, создаётся сам при первом запуске.

Проверка: `cd backend && python -m pytest` — все тесты должны пройти.

> Если путь к Python содержит русские буквы и `python -m venv` падает с ошибкой, поставьте Python в папку без кириллицы или создайте окружение через `uv venv --python 3.12 .venv`.

## В. Два ноутбука (клиент и ПВЗ)

1. Оба ноутбука — в **одной Wi-Fi сети**. Надёжнее раздать интернет с телефона: в сетях площадок устройства часто не видят друг друга.
2. На ноутбуке 1 запустите `start-lan.bat` (или `npm run dev:lan` вместо `npm run dev`). Окно покажет адреса вида `http://192.168.x.x:5173`.
3. Ноутбук 1 — `http://localhost:5173`, ноутбук 2 — адрес из окна.
4. Если Windows спросит о доступе Node.js к сети — «Разрешить» (частные сети).

Если ноутбук 2 не открывает адрес: выключите VPN/прокси на обоих; сделайте сеть на ноутбуке 1 «Частной» или откройте порт (PowerShell от администратора):
```powershell
New-NetFirewallRule -DisplayName "Polka 5173" -Direction Inbound -Protocol TCP -LocalPort 5173 -Action Allow
```
С Docker — то же самое, адрес `http://<ip ноутбука 1>:8080`.

## Г. Сервер в интернете

Подойдёт любой VPS с Ubuntu 22.04+ (1 ГБ памяти достаточно).

1. Поставьте Docker:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
2. Скачайте проект и **смените пароль базы** в `docker-compose.yml` (`POSTGRES_PASSWORD` и тот же пароль в `DATABASE_URL`). Уберите проброс порта API наружу — строку `- "8000:8000"`: интерфейс сам ходит к API внутри Docker.
3. Запустите: `docker compose up --build -d`. Интерфейс будет на `http://<ip сервера>:8080`.
4. **HTTPS и домен** (нужны, чтобы у водителя работала кнопка «Определить автоматически» — браузер даёт геолокацию только по https). Направьте домен на IP сервера и поставьте Caddy — он сам получит сертификат:
   ```bash
   sudo apt install -y caddy
   echo 'polka.example.ru {
       reverse_proxy localhost:8080
   }' | sudo tee /etc/caddy/Caddyfile
   sudo systemctl reload caddy
   ```
   Теперь система открывается по `https://polka.example.ru`.

## Настройки

| Переменная | Где | Зачем | По умолчанию |
|---|---|---|---|
| `DATABASE_URL` | сервер | адрес базы | SQLite-файл `backend/polka.db` |
| `POLKA_ROUTING` | сервер | `off` — не ходить в OSRM, строить маршруты по прямой (без интернета, в тестах) | `on` |
| `API_URL` | интерфейс в режиме разработки | куда проксировать `/api` | `http://127.0.0.1:8000` |

## Данные

- **ПВЗ Йошкар-Олы** — `backend/data/pvz.json` (20 реальных пунктов WB из OpenStreetMap + 90 модельных). Пересобрать или подставить свой список: `backend/scripts/build_pvz.py`, свой CSV — `backend/data/pvz.csv` (`name,lat,lon,address`).
- **Примерный спрос** — `backend/data/demand.json`: товаров в день на 1 000 жителей, доли категорий, доля одного ходового товара, города и их население. Цифры можно менять — расчёт поставщика пересчитается сам.
- **Демо-аккаунты** создаются при первом запуске: покупатели `ivan`, `maria`, ПВЗ `pvz1`…`pvz110`, пароль `1234`. Водителей и поставщиков регистрируют сами. Полки ПВЗ в начале пустые — товар раскладывают поставщики.
- **«Сбросить демо»** на стартовом экране удаляет заказы, рейсы, уведомления и поставки, очищает полки, водители возвращаются туда, где начинали смену. Аккаунты, зарегистрированные ПВЗ и товары поставщиков остаются.

## Частые проблемы

| Что видно | Что сделать |
|---|---|
| «Не удалось посчитать план… Запущен ли сервер?» | запустите сервер (окно «Polka API» или `uvicorn …`) и обновите страницу |
| порт 8000, 5173 или 8080 занят | закройте программу на этом порту или поменяйте порт в команде / `docker-compose.yml` |
| карта серая, без улиц | нет интернета или его режет прокси — подключите сеть |
| у водителя маршрут по прямой и подпись «Сервис маршрутов не ответил» | OSRM недоступен; система работает дальше, маршрут — по прямой |
| «Определить автоматически» не работает | откройте систему через `localhost` или https — по `http://192.168…` браузер не даёт геолокацию; отметьте место на карте |
| `docker compose` падает на Windows | запустите Docker Desktop и дождитесь «Engine running»; проверьте, что включён WSL 2 |
